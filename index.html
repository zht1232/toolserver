使用说明
  • 仅发送歌名与歌手名用于检索，不上传任何本地文件。
  • 用自带 server.py 启动网站时启用网易云源；纯静态托管自动走 LRCLIB。

多源音乐下载

默认同时检索全部音源，服务器只做搜索与直链解析，音频由浏览器直连 CDN，不经过服务器、也不存服务器。

搜索与音源
默认「全部音源」：输入关键词后回车或点「搜索」；服务器只做搜索与直链解析，音频由浏览器直连 CDN。
搜索结果
原理与边界
  • 默认「全部音源」会并行检索网易云、QQ音乐、酷狗、汽水音乐、千千、5sing，并标注每首歌的实际来源，方便在某个源不可用时换源。
  • 服务器只负责搜索与直链解析，返回歌曲元数据和临时 URL；音频字节不经过本站服务器，由浏览器直连各平台 CDN。
  • 会员曲、版权下架曲或被平台限制的歌曲可能没有可下载直链；换一个音源或版本再试，或点击失败项旁的「换源搜索」。这不是本站服务器故障。
  • 酷我、咪咕缺少跨域响应头，B 站需要 Referer，Jamendo 返回网页，浏览器无法直连下载，所以不列出；本站不做服务器中转、不落盘、不存储音频。
  • 下载内容请仅作个人学习使用，遵守各平台版权规定与当地法律。

隐私与部署

图片、音频和文本默认都在浏览器本地处理；只有你主动开启的 HIF 服务器兜底会上传所选文件。

安全设计
  • 本地处理：音乐解密、常规图片转换压缩和文本工具在浏览器内存完成，服务器不接收这些文件。
  • HIF 转换：10-bit HDR 解码与色彩映射默认在浏览器本地（WebAssembly）完成；仅当你在页面上勾选服务器兜底且本地解码失败时，所选 HIF 才会临时上传到本站服务器，仅内存处理、不落盘。
  • AI 修补：模型下载并缓存在当前浏览器；检测、修补时图片和遮罩不离开设备。
  • 可离线：除歌词检索、AI 模型首次下载与可选的 HIF 服务器兜底外，所有工具断网可用。
  • 依赖与模型：AI 去水印会按需载入 ONNX Runtime Web 与 MI-GAN / YOLO11 模型；未运行时不下载。
  • 模型许可：YOLO11 检测模型标注 AGPL-3.0；模型来源和权重信息见 第三方声明。
  • 服务器职责：静态文件、酷狗密钥表分片、歌词中转、可选的 HIF 兜底转换，以及保存用户主动提交的文字反馈。
  • 对外请求清单：歌词检索（歌名/歌手名）、密钥表分片、AI 模型与 HIF 解码器下载、用户主动提交的反馈，以及仅在本地解码失败且你允许兜底时上传的 HIF 文件。
部署

方式 A · 自带服务器（基础功能仅需 Python 3 标准库；HIF 转换需安装可选依赖）：

cd toolbox
python3 -m pip install -r requirements.txt
python3 server.py 8000

不安装 requirements.txt 时，其余工具仍可用；HIF 页的浏览器本地转换不依赖服务器，只有服务器兜底会显示不可用。首次启动会把 assets/kugou_key.xz（94 KB）解压为 70 MB 密钥表，供新版酷狗文件按需分片读取。

方式 B · 纯静态托管：整个目录交给 Nginx / Caddy / IIS 即可。歌词自动回退 LRCLIB；HIF 浏览器本地转换可用（首次加载约 1.4 MB 解码器），服务器兜底不可用；超 64 MiB 的酷狗新版文件会提示按需加载 12 MB 压缩密钥表。

server {
  listen 80;
  root /var/www/toolbox;
}

以 file:// 双击打开时：NCM 等本地工具可用；需读取掩码表的酷狗解密与联网检索不可用。

算法来源与声明

NCM 解密与 ncmdump / unlock-music 实现一致；KGM / KWM / QMC / XM 解密算法移植自 unlock-music（MIT）与 ghtz08/kugou-kgm-decoder（密钥表来自后者）。两个上游项目的官方测试向量均已通过。

本项目仅供个人对已合法获得的音频进行格式转换与备份，请尊重音乐版权。
